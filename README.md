# Bookler README

* Bookler позволяет строить wiki-like структуры с нечеткой/альтернативными иерархиями - "Booklet"
    * Технически это набор файлов (с подкаталогами), с произвольным текстовым содержимым, которое разделено на блоки - "куски информации".
    * Как это выглядит "на диске" можно посмотреть в "/test/booklets"


* Блоки могут быть тегированы, теги позволяют "смотреть" на блоки под разными углами через "virtual threads"
    * "virtual thread" генерится при "навигации" в "thread link"
    * "virtual threads" - список блоков со всех файлов текущего booklet, тегированные определенными тегами, с учетом контекста применения тегов в блоке


## Основные особенности Bookler

* иерархия, типы файлов: не навязываются
    * альтернативные иерархии на тегах полностью ортогональны файловой структуре
    * Bookler может использоваться как с MD-файлами, так и с source code любого типа. Одновременно.
    * Bookler может использовать даже без открытого каталога/workspace, опирается на файловую систему (это и плюс и минус)
    * Default: ["\*.tbd","\*.md"]

* теги: произвольное слово с определенным префиксом. Есть поддержка нескольких префиксов
    * Недопустимые символы - пробел, ",", "?", "&", "=", "[" "]", символы префиксов тега
    * Несколько префиксов удобно для визуального разделения тегов в разной семантике (когда по префиксу сразу видно к чему относится тег)
    * Default: ["@", "#"]

* теги: тегируются блоки, а не строки
    * блок - несколько строк подряд без двойных переводов строки внутри. пустые строки разделяют блоки
    * строка, на которой расположен тег в блоке, используется для определения контекста тега
    * контекста тега - слово с двоеточием в строке, где указан тег в блоке
    * например: если в блоке (несколько строк) есть строка вида "MAYBE: возможно понадобится #cool_device или помошь @cool_expert", то контекст тегов cool_device и cool_expert в этом блоке - слово "MAYBE"

* возможность иметь разные "booklets" (каждая со своими правилами) в рамках одного workspace
    * рамки booklet-а опеределяются наличием "booklet root" файла в каком-либо каталоге. Все childs этого каталога считаются относящимися к этому "booklet"-у
    * рамки booklet-а в отсутствии toc-файла: sibling files и childs files от текущего редактируемого
    * Default name для "booklet root": '_toc.tbd'

* bookler links: wiki-like ссылки вида [[...]]. При "навигации" (F12) открывают места использования, но с нечеткой логикой перехода
    * bookler links могут вести: к блоку в файле, к файлу по имени, к файлу по относительному пути
    * ищутся включение соотсветсвующего тега (с любым из префиксов)
    * логика перехода ограничена рамками booklet-а
    * можно указать несколько тегов через пробел или запятую. пример: [[cool_tagA, cool_tagB]]
    * в тегах можно использовать wildcards "*", "?" - аналогично file glob wildcard
    * если подходящих блоков несколько - результаты сортируются стабильным образом

* threads links: wiki-like ссылки вида [[?:...]]. При "навигации" (F12) создают временный список блоков из разных файлов
    * тегированные блоки собираются в единый notebook (в temp) с возможностью редактирования каждого блока
    * такой подход позволяет смотреть блоки по нужным тегам в одном месте, причем с удобным порядком/группировкой
    * сортировка блоков в notebook - стабильная, блоки не "скачут" без причины (изменения запроса/содержимого)
    * при "исполнении ячейки" изменения в блоке вносятся в исходный файл откуда этот блок был взят
    * - это позволяет редактировать блоки без открытия исходных файлов
    * формат ссылки похож на язык поисковых запросов Google - разделенние по пробелам, по запятой, особые параметры вида param:value
    * - можно указывать несколько "positive tags". пример: [[?:cool_tagA cool_tagB,cool_tagC]]
    * - можно указывать "negative tags" - блоки с этими тегами будут проигнорированы. пример: [[?:cool_tagA cool_tagB -notcoolTagA -notcoolTagB]]
    * - можно задавать "context sort" - это меняет дефолтную сортировку по файлам на сортировку по контексту использования тегов. пример: [[?:cool_tagA cool_tagB context:IMPORTANT context:MAYBE]]
    * - особое значение "context sort" - "amust!". Блоки с подходящими тегами, но БЕЗ контекста будут проигнорированы. пример: [[?:cool_tagA context:IMPORTANT context:amust!]]
    * - можно задавать "file scope" - будут использованы блоки только из подходящих файлов. пример: [[?:cool_tagA cool_tagB file:sidenotes*.*]]
    * - особое значение "file scope" - "this!". Будут использованы блоки только из текущего файла. пример: [[?:cool_tagA -notcoolTagB file:this!]]
    * - "positive tags", "negative tags", "file scope": при поиске засчитывается любое вхождение подстроки, могут содержать wildcards "*", "?" (аналогично file wildcards)

## Extension Settings

* `bookler.bookletRootFiles`: name of the booklet root file
    * Such file mark a root for underlying booklet hierarchy and may contain booklet options and virtual threads links (for example)
* `bookler.collectFilesByName`: file globs, only matched files will be used for navigation and virtual threads
    * glob format docs: https://github.com/ev3dev/vscode-ev3dev-browser/wiki/Glob-Patterns, https://www.npmjs.com/package/fast-glob
    * must contain bookletRootFiles extensions too
* `bookler.ignoreFilesByName`: file globs, matched files/folders will skipped to speedup things
* `bookler.ignoreFilesBySize`: number of bytes, bigger files will be skipped too
* `bookler.contentTagPrefix`: prefixes, that turn words into tags
